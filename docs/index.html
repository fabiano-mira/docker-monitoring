Overview

The stack combines a Docker Compose deployment with three components that run natively on macOS, because they need direct host and network access that containers on Docker Desktop cannot get.

Host metrics

Netdata runs natively via Homebrew and reports real macOS CPU, RAM, disk, GPU and battery, plus an SNMP collector polling the router. Prometheus scrapes it over /allmetrics.

Router telemetry

A UniFi Dream Router at 10.9.1.1 is polled over SNMPv2c by snmp_exporter for standard IF-MIB counters, and exports NetFlow/IPFIX to the Mac for per-flow analysis.

Dual flow pipelines

Two collection paths run side by side: goflow2 → Loki/InfluxDB v2 for queryable per-flow records, and netflow2ng → ntopng for a live ZMQ flow stream with its own timeseries store.

Provisioned as code

Grafana auto-provisions data sources and every dashboard from files on each start. No manual UI setup, and nothing is lost when a volume is wiped.

Architecture

The router only supports a single NetFlow export target, so it points at a small native relay that duplicates each datagram to both collectors.

Native components

Three pieces run outside Docker, since they need direct macOS/network access:

Netdata
Homebrew, config in /opt/homebrew/etc/netdata/. Real host metrics plus the go.d/snmp collector polling the router.
goflow2
~/bin/goflow2, managed by LaunchAgent com.netsampler.goflow2.plist. Receives NetFlow/IPFIX on UDP 2055, writes JSON records to ~/Library/Logs/goflow2/flows.log, exposes Prometheus metrics on :8080.
netflow-relay.py
scripts/netflow-relay.py, managed by LaunchAgent com.netmon.netflow-relay.plist. Receives the router's single export on UDP 2057 and fans each packet out to goflow2 (2055) and netflow2ng (2056).

Quick start

Prerequisites

  • Docker Desktop (context desktop-linux)
  • Homebrew with netdata running (brew services start netdata)
  • goflow2 running as a LaunchAgent, listening on UDP 2055
  • scripts/netflow-relay.py running as a LaunchAgent, listening on UDP 2057
  • Router exporting SNMP (v2c, community public) and NetFlow/IPFIX to this Mac's LAN IP on port 2057

Deploy

git clone https://github.com/fabiano-mira/docker-monitoring.git
cd docker-monitoring
docker compose up -d

This brings up all 12 containers. Grafana provisions its data sources and dashboards from files on every start, so no manual UI setup is required.

Install the NetFlow relay (one-time)

cp launchagents/com.netmon.netflow-relay.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.netmon.netflow-relay.plist

Verify after a reboot

./check-health.sh

Validates the Docker daemon and all 12 containers, the three native components, UDP listeners on 2055/2057, every HTTP endpoint, Prometheus scrape targets, Grafana datasource health, and end-to-end data freshness in both NetFlow pipelines. Exits non-zero with a fix hint per failed check.

Known limitations

  • node_exporter reflects Docker Desktop's LinuxKit VM, not the real Mac. Use the Netdata-backed dashboards for genuine host metrics.
  • ICMP ping sub-checks fail in Netdata's SNMP collector — macOS restricts raw ICMP sockets for unprivileged processes. SNMP metric collection is unaffected.
  • goflow2 counters reset on process restart. If flow dashboards go empty, check ~/Library/Logs/goflow2/stderr.log and confirm the router still targets this Mac's current LAN IP.
  • Telegraf requires watch_method = "poll" — inotify events don't reliably cross the Docker Desktop bind-mount bridge.
  • ntopng only supports InfluxDB 1.x, so a separate influxdb-ntopng container exists purely for its timeseries data.
  • ntopng's --local-networks only affects host classification, not which flows are received.
  • ntopng preferences live in redis-ntopng, not in version control, and must be re-applied if that volume is wiped.
  • --disable-login needs an explicit 0/1 argument, or ntopng's parser swallows the next list item in docker-compose.yml.
  • The UniFi router supports a single NetFlow destination, which is why netflow-relay.py fans the export out to both collectors.
  • The ntopng datasource uses InfluxQL, not Flux — panel targets use {"query": "SELECT ...", "rawQuery": true}.
  • ntopng does not write per-host timeseries (e.g. host:traffic), only interface-level aggregates. Use the Infinity-backed Live Hosts dashboard instead.
  • Infinity queries require "parser": "backend", or columns selectors silently return an empty table.
  • The Live Flows node graph can transiently warn about missing nodes, since nodes and edges come from two separate ntopng API calls. A refresh clears it.
